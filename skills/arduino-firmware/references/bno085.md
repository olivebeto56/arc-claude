# BNO085 — Referencia Técnica para Firmware Arduino

## Identificación del chip
- Fabricante: CEVA / Hillcrest Labs (ahora parte de Bosch)
- Chip: BNO085 (o BNO080 — mismo silicon, diferente encapsulado)
- Procesador interno: ARM Cortex-M0+ con firmware CEVA SH-2
- Interfaces: I2C (hasta 400kHz), SPI, UART

## Dirección I2C
- Default: **0x4A** (cuando el pin SA0/ADDR está a GND o flotante)
- Alternativa: **0x4B** (cuando SA0 está a VCC)
- En el breakout de Adafruit (#4754): SA0 está a GND por defecto → usa **0x4A**

## Inicialización con la librería Adafruit BNO08x

```cpp
#include <Adafruit_BNO08x.h>

Adafruit_BNO08x bno085(-1);  // -1 = sin reset pin

bool initSensor() {
  Wire.setClock(400000);  // Fast mode I2C — IMPORTANTE para 100Hz+
  
  if (!bno085.begin_I2C(0x4A)) {
    Serial.println("ERROR: BNO085 not found at 0x4A");
    return false;
  }
  
  // Activar reporte de rotación con magnetómetro (9 ejes)
  // NUNCA usar GAME_ROTATION_VECTOR — omite el magnetómetro
  if (!bno085.enableReport(SH2_ARVR_STABILIZED_RV, 10000)) {  // 10000 us = 100Hz
    Serial.println("ERROR: Could not enable rotation vector report");
    return false;
  }
  
  // Opcional: también activar acelerómetro lineal (sin gravedad)
  bno085.enableReport(SH2_LINEAR_ACCELERATION, 10000);
  
  return true;
}
```

## Tipos de reportes disponibles (SH2 Report IDs)

| Constante | Descripción | Ejes | Usar para |
|---|---|---|---|
| `SH2_ROTATION_VECTOR` | Cuaternión absoluto (9 ejes) | Accel+Gyro+Mag | Golf, postura |
| `SH2_ARVR_STABILIZED_RV` | Igual que arriba + estabilización para AR/VR | Accel+Gyro+Mag | **Recomendado para deportes** |
| `SH2_GAME_ROTATION_VECTOR` | Cuaternión relativo (6 ejes) | Accel+Gyro | ⚠️ NO usar — sin magnetómetro, hay drift en Z |
| `SH2_LINEAR_ACCELERATION` | Aceleración sin gravedad | Accel | Detección de impacto, cadencia |
| `SH2_GYROSCOPE_CALIBRATED` | Velocidad angular | Gyro | Velocidad de swing |
| `SH2_STEP_COUNTER` | Contador de pasos | - | Running (complementario) |
| `SH2_STABILITY_CLASSIFIER` | Clasificador de movimiento | - | Detección de actividad |

## Lectura del sensor en el loop

```cpp
#include <sh2.h>
#include <sh2_SensorValue.h>

sh2_SensorValue_t sensorValue;

bool getSensorAngles(SensorAngles& out) {
  if (!bno085.getSensorEvent(&sensorValue)) {
    return false;  // No hay dato nuevo disponible
  }
  
  if (sensorValue.sensorId == SH2_ARVR_STABILIZED_RV) {
    out.qw = sensorValue.un.arvrStabilizedRV.real;
    out.qx = sensorValue.un.arvrStabilizedRV.i;
    out.qy = sensorValue.un.arvrStabilizedRV.j;
    out.qz = sensorValue.un.arvrStabilizedRV.k;
    
    // Convertir cuaternión a ángulos de Euler (grados)
    // Roll (X), Pitch (Y), Yaw (Z)
    float sinr_cosp = 2.0 * (out.qw * out.qx + out.qy * out.qz);
    float cosr_cosp = 1.0 - 2.0 * (out.qx * out.qx + out.qy * out.qy);
    out.roll = atan2(sinr_cosp, cosr_cosp) * 180.0 / M_PI;

    float sinp = 2.0 * (out.qw * out.qy - out.qz * out.qx);
    out.pitch = (abs(sinp) >= 1) ? copysign(90.0, sinp) : asin(sinp) * 180.0 / M_PI;

    float siny_cosp = 2.0 * (out.qw * out.qz + out.qx * out.qy);
    float cosy_cosp = 1.0 - 2.0 * (out.qy * out.qy + out.qz * out.qz);
    out.yaw = atan2(siny_cosp, cosy_cosp) * 180.0 / M_PI;
    
    out.timestamp_ms = millis();
    return true;
  }
  return false;
}
```

## Calibración

El BNO085 tiene calibración automática (en memoria volátil). Para calibración persistente:

```cpp
// Guardar calibración en flash del BNO085
sh2_saveDcdNow();

// La calibración se pierde con el reset. Para movimientos de alta precisión
// (golf), esperar a que el estado de calibración sea bueno antes de grabar:
// sensorValue.status: 0=sin calibrar, 1=bajo, 2=medio, 3=completamente calibrado
```

## Frecuencias de reporte y timing

El segundo parámetro de `enableReport()` es el intervalo en **microsegundos**:
- 100 Hz → 10,000 µs
- 200 Hz → 5,000 µs  
- 50 Hz → 20,000 µs
- 25 Hz → 40,000 µs

**Nota:** El BNO085 puede no entregar exactamente la frecuencia solicitada. Para 200Hz puede necesitar SPI en lugar de I2C (I2C tiene límite práctico de ~250Hz).

## Conexión física con XIAO nRF52840

```
BNO085 Stemma QT  →  XIAO nRF52840
─────────────────────────────────
VCC (rojo)        →  3.3V
GND (negro)       →  GND
SDA (azul)        →  D4 (SDA / P0.06)
SCL (amarillo)    →  D5 (SCL / P0.07)
```

## Errores frecuentes

**"BNO085 not found"**
- Verificar que `Wire.begin()` se llamó antes de `bno085.begin_I2C()`
- Verificar que los cables no estén invertidos (SDA↔SCL)
- Agregar `delay(100)` después de `Wire.begin()` para dar tiempo al sensor de arrancar

**Cuaternión siempre (1, 0, 0, 0)**
- El sensor no ha completado su arranque interno. Esperar 500ms-1s después de `begin_I2C()` antes de empezar a leer.

**Datos congelados / no se actualizan**
- El sensor puede estar en modo SHTP de baja energía. Verificar que `enableReport()` devuelve `true`.
- Revisar si hay algún `delay()` largo en el loop que bloquee la lectura del bus I2C.

**Ruido excesivo en los ángulos**
- Usar `SH2_ARVR_STABILIZED_RV` en lugar de `SH2_ROTATION_VECTOR` — tiene filtrado adicional.
- El magnetómetro puede interferir con motores o imanes cercanos. En ese caso, usar `SH2_GAME_ROTATION_VECTOR` solo para movimientos cortos (< 30 segundos).
